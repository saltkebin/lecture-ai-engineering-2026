# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：素のLLMはモデル自身の事前学習データ（知識）のみに基づいて一般的な解説や一般的な問題を生成するが、エージェントは search_glossary や make_quiz などの独自ツールを呼び出し、講義専用の用語集（glossary.json）の正確な定義に基づいた確認問題と解答を出力できる点。
- `--trace` で見えたツール呼び出し（ツール名と引数）：[tool call] make_quiz({'lecture': 2})
- 1つの質問での LLM 呼び出し回数（`requests`）：2回（ユーザー入力からツール呼び出しを決定するのに1回、ツールの実行結果を受け取って最終的な回答文を生成するのに1回の計2回）
- 追加したツールと、docstring に書いた説明：追加したツール: make_quiz

docstring:

Python
"""指定した回の用語から1つを選び、
確認問題と答えを返す。

「第2回の確認問題を出して」のように、
復習用の問題を求められたときに使う。
"""

取り組んだレベル：基礎

やったこと：
app/agent.py の INSTRUCTIONS から「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の行を削除し、変更前後で同じ質問（uv run python -m app.agent --trace "LoRAとは何ですか？"）を実行して挙動を比較した。

結果：
input_tokens は 1091 から 1043 へと減少し指示の削除が反映されたが、ツールの呼び出し挙動（search_glossary({'query': 'LoRA'}) が1回実行され、requests=2 となる点）や用語集に基づいた回答内容自体には変化が見られなかった。

気づき・疑問：
エージェント全体のシステム指示（INSTRUCTIONS）からツール使用の強制文を削除しても、ツール側（app/tools.py）の docstring に「答える前に使うこと」と強く書かれている場合、モデルはツールの説明文を読んで自律的に呼び出しを判断することが分かった。ツールの呼び出しを制御するには、プロンプトだけでなく docstring 側の指示の強さも合わせて調整する必要があるのではないかと感じた。
